Your own world, from download to login

The setup kit installs and starts a compatible revision 225 game server and serves the LoreScape launcher with it. GitHub Pages serves this download; your computer runs the world.

Download local server setup (.zip)

Install on Windows, macOS or Linux

  1. Install Node.js 22.22.1 or newer, Git, and Java 17 or newer. Linux may also need Python 3, make and a C++ compiler for native packages.
  2. Extract the entire ZIP into a writable folder. Open a terminal in that extracted folder.
  3. Run node setup.cjs. Keep internet connected: it downloads the pinned 2004Scape server, installs dependencies, and builds game and tool data. Allow several minutes.
  4. When setup finishes, run node start.cjs. The first launch packs game data and may take several minutes. Wait for World ready.
  5. Open http://127.0.0.1:8080/ on that computer. Keep the terminal open while playing. Select Existing user; a new name creates a save in this development world. Use a throwaway password: this private mode has no account authentication.

Next time, run node start.cjs. Stop with Ctrl+C. Stop the server before re-running setup. Saves are in server/data/players/; back them up before reinstalling. Setup preserves existing saves, settings and installation keys. The built-in tools connect to your local world automatically, including the map and chat-animation data built during setup.

Locked-down Chromebook options

Without Linux support, a managed Chromebook cannot install this game server. Downloading a cache or opening the ZIP will not start a world. These options use Chrome without an extension:

  • Play a public world: return to the launcher, choose an available world and use low detail for a lighter client. The world’s services must be online and permitted by your administrator.
  • Use a hosted world: run the kit on another computer or server and open its HTTPS launcher URL on the Chromebook. A host can follow the instructions below. Your Chromebook needs no local server or software installation.
  • Use the cache tools: choose Download cache for tools in the launcher, then open that ZIP in Cache viewer or JagEd. Extracted folders work too. Downloads and file imports must be permitted. If browser storage is blocked, imports work for the current tab; select the ZIP again after reloading.

A school or workplace may block game sites or WebSocket connections. Ask the administrator to allow the host. This setup does not change or bypass device policies.

Host for another device

On the server computer, give the launcher a trusted HTTPS address. For example, install Caddy on the same host, point your domain at it, and use this Caddyfile:

play.example.com {
    reverse_proxy 127.0.0.1:8080
}

Set the public address before starting the kit. macOS/Linux:

LORESCAPE_PUBLIC_ORIGIN=https://play.example.com node start.cjs

Windows PowerShell:

$env:LORESCAPE_PUBLIC_ORIGIN='https://play.example.com'
node start.cjs

Open https://play.example.com/ on the Chromebook. The root link selects the server address and its login key automatically. The proxy forwards both files and WebSockets on the same origin. Keep the generated setup=1 parameter when sharing the launcher link.

The installer restricts backend ports 8888, 8898 and 43594 to loopback. The kit’s gateway also listens on loopback port 8080 by default. Keep those ports private. Share access only with people you trust: this is a private development world. For public community accounts, use the upstream authenticated production setup. Never publish the server folder, private keys, settings or saves.

If setup stops

  • Missing prerequisite / install failure: read the first terminal error, install the missing program or build tools, then retry node setup.cjs.
  • Port in use: stop the old server or other program using the named port.
  • 503 or missing game files: wait for World ready and check the server terminal for errors.
  • Login out of date: reopen the root address printed by start.cjs. It supplies the matching installation key.

The kit uses archived upstream revision 647886c42f8a22c0f18e5dbe79c2697f052f8d2e and includes a tested dependency lockfile for reproducible installation. Package availability and platform support can affect setup. Its MIT license is included in the downloaded server source. Full instructions are also in the ZIP’s README.txt.

The kit updates bcrypt and Kysely to remove known installer and SQL-builder advisories. One upstream node-forge signature-verification advisory has no published fix as of October 17, 2026. The local server uses RSA key parsing/arithmetic rather than signature verification; this remains a dependency limitation. See the ZIP README for details.
